## Exception: Model Gateway (Tool-Calling Substrate) — 🟢 DONE

One piece of `PLAN.md`'s own scope (§1 "Model gateway" — provider routing, tenant-attributed calls, budget ceilings, kill switch, token accounting) was pulled forward and built as its own narrower slice, exactly matching the user's own supplied target architecture document's §35 "Recommended First Implementation" (confirmed via `AskUserQuestion`): AI Orchestrator + Tool Registry + Gemini provider + AI audit trail + a read-only AI Command Center. See ADR-045 for the full design reasoning. Gates re-run and green, not assumed:

- **Model Gateway port + Gemini adapter** (`6fd078d`): `ModelGatewayPort` (`application/ai/ports.py`) — one method, `run_with_tools()`, taking a `tool_executor` callback the application layer supplies; the port never knows what a "tool" means business-wise. `GeminiModelGateway` (`infrastructure/ai/gemini_adapter.py`) built against the real installed `google-genai` SDK (not guessed) — its tool-calling turn/role shape confirmed by reading the SDK's own internal automatic-function-calling reference implementation. `infrastructure/ai/factory.py`'s provider selection is the entire "provider configurable" story: a second provider means one new adapter class + one new branch, nothing else changes. New `ai` schema migration (`ai.assistant_run` append-only ledger + `ai:read` permission, granted only to `super_admin, agency_admin, manager`), two new `TenantConfiguration` keys (`ai_gateway_enabled` default-off kill switch mirroring `weighment_gate_enabled`'s shape — ADR-040; `ai_daily_token_budget` override). 7 new unit tests (mocked SDK, no real network calls).
- **Tool Registry + read-only tools** (`3adb869`): `application/ai/tools.py` — `TOOL_REGISTRY`, a static, code-defined list of zero-argument tools, each declaring a `required_permission` the orchestrator filters against before Gemini ever sees the tool exists. Three tools: `get_today_delivery_status` (the one genuinely new query — no existing use case answered "today's order-status counts" or "delayed" at all; narrowed to a `stale_out_for_delivery_count` signal), `get_inventory_overview` (wraps an existing repository method with no use case of its own yet), `get_open_complaints_summary` (three `count_complaints` calls, one per non-terminal status). 7 new unit tests (mocked repositories, no database).
- **`AskAiAssistantUseCase` + `POST /ai/ask`** (`b103a8a`): kill switch and budget checked in the use case before the gateway is ever touched (mirrors `weighment_gate_enabled`'s check-in-the-use-case shape exactly), per-tool permission filtering, a hallucinated or out-of-grant tool call rejected by the `tool_executor` closure and never executed — the real prompt-injection defense per the user's own architecture document. New `ai.assistant_run` append-only run ledger, rides the existing generic `AuditRecorder` hook for a free audit trail — no bespoke audit-write path. 6 new unit tests plus a 3-test integration smoke test through the real ASGI stack (auth, RBAC, RLS, DB) with the gateway overridden by a fake, proving the kill-switch/budget/permission-filtering/ledger-write path end to end without a real Gemini call.
- **Frontend client regen** (`c8d242a`): OpenAPI + Angular client regen for `POST /ai/ask`.
- **AI Command Center page** (`aba1698`): new `ai/feature-ai-assistant` lib, route `/ai-assistant` (`ai:read` guard), nav link. A single-question interface (no cross-request conversation memory — each question is independent, matching the deliberately narrow scope), a "Data from: X, Y" transparency footnote built from which tools were actually consulted, and specific (never a raw error toast) messaging for each `disabled_reason`. Also added `ai_gateway_enabled`/`ai_daily_token_budget` to the Tenant Configuration page's key catalog so an admin can actually discover and set them.
- **A real bug caught by live verification, not by any test written before it was found**: the generic Tenant Configuration admin form has no dedicated toggle for `ai_gateway_enabled` — it persists whatever string an operator types, so `config_value` can be the literal string `"false"`, not the JSON boolean `false`. A naive `bool(config_value)` reads that as truthy (`bool("false") is True` in Python), so a tenant "disabled" through the real admin UI was actually still answering questions. Caught live: set the flag to `"false"` through the real page, asked a real question, got a real answer instead of the disabled message. Fixed with a dedicated `_is_truthy_config_value()` helper (string-aware) plus a regression test asserting the literal string `"false"` disables the gateway. Named as a live risk for `weighment_gate_enabled` too (same generic-form, same `bool()`-cast shape) — not fixed there, out of scope for this slice.
- **Live-verified end-to-end with a real Gemini API key** (not mocked): asked "What's today's inventory situation and are there any open complaints right now?" — the model correctly called both `get_inventory_overview` and `get_open_complaints_summary`, and the numbers matched the dashboard exactly (2,606 filled / 923 empty / 9 damaged / 1 leakage; 6 open complaints). Asked "Why might deliveries be delayed today?" — the model autonomously called all three tools and correctly identified the 9 stale `out_for_delivery` orders (the one genuinely new query) as the real signal, cross-referencing complaints and inventory as supporting context — exactly the "AI reasons across tools" behavior the user's own architecture document describes. Confirmed the disabled state renders correctly both before enabling and after disabling. The Gemini model name (`gemini-2.0-flash`, current at implementation time) was found retired during this live check — the provider's own 404 response named the real current model (`gemini-3.6-flash`), and `Settings.gemini_model`'s default was corrected before shipping.
- **Docs** (this commit): ADR-045 (the tool-calling port shape, per-tool permission filtering as the real prompt-injection defense, the live-bug-caught-by-verification finding), this STATUS.md, and `23-ai-assistive-interfaces/STATUS.md` (this slice is also that phase's own narrowed A12 precursor).
- **Gates:** targeted `uv run pytest` (7 + 7 + 6 = 20 new unit tests + 3 new integration tests, all passing) plus bare `uv run ruff check`/`uv run mypy` clean on every touched backend file; full backend regression re-run after every stage (931 unit + 399 integration, zero regressions); new "Gemini SDK stays inside infrastructure.ai" import-linter contract added and confirmed KEPT; `frontend` lint/build/test all clean for every touched/new library (`ai-feature-ai-assistant`, `shared-data-access`, `dashboard`, `admin-feature-tenant-settings`); every UI surface live-verified in-browser against the real dev backend **and a real Gemini API key**, not just unit-tested or mocked.

**Explicitly deferred, not silently dropped** (carried forward from ADR-045 and `PLAN.md`'s own broader scope):

1. **Feature store, evaluation harness, inference serving (batch scoring), full guardrails/governance (PII redaction pipeline, DPDP retention policy for prompt/response capture)** — this phase's own remaining, much larger scope; `ai.assistant_run` deliberately does not store prompt/response text bodies, precisely because that retention-policy question hasn't been resolved.
2. **A DB-backed, admin-configurable tool registry** — three tools, all read-only, all zero-argument, is small enough that a static, code-reviewed list is the safer and simpler choice for this slice; a dynamic registry needs its own authorization model, not yet designed.
3. **Parameterized tools** (date ranges, specific customers) — every v1 tool is zero-argument; a natural, easy follow-up once this pattern is proven.
4. **Branch-level scoping for the tools** — order/route branch-scoping today lives in two different private router functions with no reusable application-layer helper, and inventory/complaints have no branch concept at all; the tools are tenant-wide (RLS-isolated), not further narrowed.
5. **The `weighment_gate_enabled` string-vs-boolean risk** identified above — a live, real risk in existing shipped code (ADR-040), named explicitly, not fixed as part of this slice.

**This does not move the file's own `State` above off NOT STARTED** — the Model Gateway is one substrate slice out of Phase 21's much larger backlog (feature store, evaluation harness, inference serving, full governance all remain untouched).
